# 📝 Рекомендації до реалізації — WorkTracker Update

Цей документ містить технічні вимоги та пропозиції щодо вдосконалення архітектури, безпеки та функціональності проекту.

---

## 🔐 1. Безпека та Авторизація (Telegram Auth)

> [!IMPORTANT]
> **Статус:** Рекомендується до реалізації у наступному спринті.

### Опис
На даний момент додаток використовує `telegram_id` без серверної перевірки. Необхідно впровадити механізм валідації `initData` на стороні сервера для запобігання підробці даних.

### Технічні вимоги
1. **Middleware для перевірки:**
   - Впровадити серверний метод (наприклад, у Supabase Edge Functions) для перевірки `hash` з `initData`.
   - Використовувати секретний `BOT_TOKEN` (збережений у змінних оточення) та константу `"WebAppData"`.
   - Алгоритм: HMAC-SHA256.

2. **Інтеграція з Supabase Auth:**
   - Після успішної перевірки створювати/оновлювати сесію користувача в Supabase.
   - Замінити використання `telegram_id` як єдиного ідентифікатора на використання валідних JWT токенів.

3. **Row Level Security (RLS):**
   - Налаштувати політики безпеки в таблицях `orders`, `time_logs`, `advances`, щоб кожен користувач мав доступ лише до своїх даних (через `auth.uid()`).

## 💾 2. Локальне Тестування (LocalStorage Strategy)

> [!IMPORTANT]
> **Статус:** Рекомендується до реалізації для можливості автономного тестування флоу.

### Опис
Для тестування повного життєвого циклу замовлень (створення, редагування, зміна статусів) без підключення до живого Supabase, необхідно реалізувати проміжний рівень збереження даних у `localStorage` браузера.

### Технічні вимоги
1. **Механізм перемикання:**
   - Додати у `dataService.ts` перемикач `USE_LOCAL_STORAGE`.
   - Якщо `USE_LOCAL_STORAGE=true`, усі операції CRUD мають виконуватися з даними у `localStorage`.

2. **Персистентність:**
   - При першому запуску ініціалізувати `localStorage` базовими моковими даними.
   - Усі зміни (нове замовлення, оновлення балансу) мають одразу записуватися в `localStorage`.

3. **Сумісність інтерфейсу:**
   - Методи `getOrders`, `createOrder`, `updateStatus` мають повертати Promise, щоб імітувати асинхронність мережі.
