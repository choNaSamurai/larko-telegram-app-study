# ADR Template for Telegram Mini App

Follow this structure for every Architectural Decision Record.

## Title: ADR-[ID]: [Decision Name]
**Status**: [PROPOSED | ACCEPTED]

## Context
Describe the current state, technical environment, and constraints.
- Project Scope: [e.g. Shift Management]
- TMA Constraints: [e.g. Telegram WebApp, Data size limits]

## Problem
What specific technical challenge are we solving? 
- "How to handle real-time updates?"
- "Which database model is best for X?"

## Options Considered

### Option 1: [Name]
- Pros: ...
- Cons: ...

### Option 2: [Name]
- Pros: ...
- Cons: ...

## Decision
Clear statement of the chosen path.

## Rationale
Why this choice is better for the current MVP and TMA context.
- MVP Speed
- Team Familiarity
- Performance

## Consequences
- **Positive**: What we gain.
- **Negative**: Technical debt or trade-offs.

## Future Considerations
Scaling plan for the next 12 months.
